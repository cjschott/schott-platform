# CINV-000003 STAGE 2 -- `capability authorise-launch`, exactly as it is to be
# typed.
#
# This file is reference text, not a script to run: the operator pastes each
# block into a shell so every command and every refusal is visible on the
# console.
#
# =====================================================================
# THREE BLOCKS, AND ONLY ONE OF THEM MUTATES
# =====================================================================
#   BLOCK A  observation, as kyri-capability. Containers and the execution
#            image. Writes a witness.
#   BLOCK B  the gates. Read-only, every one of them.
#   BLOCK C  the single irreversible command, and what must be true after it.
#
# WHY BLOCK C IS SEPARATE, AND WHY IT IS NOT REHEARSABLE HERE
# ===========================================================
# `authorise-launch` COMPILES IN its roots -- the runtime store, the execution
# root, the handoff root -- and takes no `--store-root`. That is deliberate and
# was re-affirmed at Generation 20: the privileged transition on the far side
# compiles in the same roots, so the ceremony and its consumer agree by
# construction rather than by an operator keeping two flags consistent.
#
# The consequence has to be said plainly, because on 2026-09-20 it was not.
# A rehearsal that substitutes paths through this file would redirect every
# gate in BLOCK B and would NOT redirect BLOCK C. The gates would read a
# fixture and the mutation would land in production. That is exactly the
# incident this project has already had.
#
# So BLOCK C IS NEVER RENDERED AGAINST A FIXTURE. The rehearsal of its effect
# lives at the API, in tests/test-capability-cinv-000003-stage-2-rehearsal.sh,
# which calls `launch.authorise_launch` with roots it passes explicitly. The
# suite asserts that BLOCK B alone is what it runs.
#
# WHAT STAGE 2 IS
# ===============
# It carries the prepared invocation to a verifiable handoff and stops. It
# reserves one execution slot, transitions reserved -> launch_authorized,
# journals a launch-authorisation projection, and publishes the handoff tree
# the privileged boundary will later consume.
#
# WHAT STAGE 2 IS NOT
# ===================
# It starts no container, runs no payload, writes no CRES, and allocates no
# identity. It does NOT re-check Fabric eligibility and it does NOT consult
# Trust -- the released bridge says so in terms, and reads the selection and
# package back from CINV-000003's own durable record. **Every current-authority
# question is therefore BLOCK B's job, not the command's.** That is the whole
# reason BLOCK B exists.
#
# THE AUTHORITY EXPIRES ON 2026-09-23T06:00:00-05:00
# ==================================================
# CADV-000007 carries that `valid_until`. Stage 2 must run before it, or the
# advertisement must be renewed and this ceremony re-prepared against the new
# chain. BLOCK B asks the released verifier, at the moment it runs, rather than
# comparing dates by eye.
