# CINV-000003 STAGE 3 -- `capability execute`, exactly as it is to be typed.
#
# This file is reference text, not a script to run: the operator pastes each
# block into a shell so every command and every refusal is visible on the
# console.
#
# =====================================================================
# THREE BLOCKS, AND ONLY ONE OF THEM MUTATES
# =====================================================================
#   BLOCK A  observation, as kyri-capability. Containers and the execution
#            image. Writes a short-lived witness.
#   BLOCK B  the gates. Read-only, every one of them.
#   BLOCK C  the single irreversible command, and what must be true after it.
#
# BLOCK C IS NOT REHEARSABLE, FOR THE REASON STAGE 2's WAS NOT. `execute`
# compiles in its runtime root, and `supervised_binding` compiles in the
# execution root it reads the authorisation from. A path substitution through
# this file would redirect every gate in BLOCK B and would not redirect the
# mutation. That is the 2026-09-20 incident, and it is not repeated here: the
# effect of BLOCK C is rehearsed at the API in
# tests/test-capability-cinv-000003-stage-3-rehearsal.sh.
#
# =====================================================================
# WHAT STAGE 3 DOES, AND THE ONE THING IT DOES NOT
# =====================================================================
# It supervises the privileged execution and writes the one record the first
# two stages deliberately left unwritten: a `CRES`. That is its ENTIRE mutation
# of the capability runtime -- one result record and one sequence increment.
#
# IT WRITES NO LIFECYCLE TRANSITION, AND THIS IS DELIBERATE. The journal is
# written by `authorise_launch` before the privilege boundary is crossed and is
# immutable thereafter; the states past `launch_authorized` are worker-side
# protocol states that exist on the wire and never in the journal. G11-BC-I
# established this as specified behaviour, not a defect.
#
# THE CONSEQUENCE HAS TO BE SAID BEFORE THE COMMAND IS RUN. After this,
# CINV-000003 will hold a terminal result and still stand at
# `launch_authorized`, holding its execution slot with no released path to
# advance or release it. That is exactly the condition CINV-000002 was
# administratively abandoned for under ADR-0015, reason
# `terminal-result-lifecycle-stranded`. Occupancy stays 2 of 2, and both slots
# will then be held by invocations that cannot move.
#
# Nothing here fixes that, and nothing here should: it is an architectural
# decision for the reviewer, not a step to bolt onto an execution ceremony.
#
# =====================================================================
# WHAT THE PAYLOAD IS EXPECTED TO PRODUCE
# =====================================================================
# The capability performs `verify-execution-boundary`, and the payload asks for
# exactly that -- which is the correction G11-BC-J made after CRES-000001
# recorded `provider-error` because the payload had asked for `execute`.
#
# The result is deterministic. For these payload bytes the package writes
# exactly 281 bytes:
#
#   {"capability":"kyri-execution-boundary-verification",
#    "checksum":"57b6b93ffd50cce4df4c8af4fd40d9b16494b884f666490257c66ff2dd274de1",
#    "operation":"verify-execution-boundary",
#    "payload_digest":"591d4b0d9c81fd5cbb56f7a08a8e9b14ef116c8625b16b19311f75d27d3c59b3",
#    "result_schema_version":1}
#
# whose SHA-256 is
#   fd2d58e99bae82f32ce320a3d3ac2a35b6e679b87432b2aedd9de1efa92cbad7
#
# and that is the digest the verdict must carry. It was computed from the
# released package and the published payload, and the rehearsal ran the package
# to confirm it.
#
# THE AUTHORITY EXPIRES ON 2026-09-23T06:00:00-05:00. CADV-000007 carries that
# `valid_until`. BLOCK B asks the released verifier at the moment it runs.

  test -n "${got}" || { echo "REFUSE: ${path} is absent"; exit 1; }
  test "${got}" = "${wanted}" \
    || { echo "REFUSE: ${path} is ${got}, expected ${wanted}"; exit 1; }
