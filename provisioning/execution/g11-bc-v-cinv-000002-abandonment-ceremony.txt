#      code.

# This closes it, permanently and administratively, and reclaims its slot.
#
# IT IS NOT A REPAIR AND NOT A FORCE. `capability abandon` takes one CINV, one
# controlled reason from a closed set the parser enforces, and NO target state:
# there is no --to, no --force and no --state. It deletes nothing. CINV-000002,
# CRES-000001, the launch authorisation and the published handoff are all left
# exactly as they are, and this block proves it by digest afterwards.
#
# IT DOES NOT CLAIM THE INVOCATION COMPLETED. `abandoned` is not `released`.
# `released` means the work ran and was classified, collected and cleaned.
# `abandoned` means the invocation was permanently administratively closed
# WITHOUT asserting any of that. The difference is the point, and ADR-0015 is
# why the two are separate states rather than one convenient one.
#
# IT FABRICATES NO EXECUTION EVIDENCE. No CRES is written. CRES-000001 already
# exists and is referenced, not rewritten.
#
# MAXIMUM_SLOTS IS UNCHANGED at 2. The ceiling was never the defect; the defect
# was that a slot could never be given back.
#
# =====================================================================
# THE ORDER, AND WHY BLOCK A COMES FIRST
# =====================================================================
#
# Abandoning an invocation removes it from the recovery enumeration. If a
# container could still exist for it, this would close the one surface that
# would have found it. The engine does not attempt to prove container absence
# -- that is what `recover` and the reconciliation verbs are for -- so the
# OPERATOR proves it here, before the closure, and BLOCK B gates on the witness.
#
# This reclaims ONE slot. CINV-000001 is a separate ceremony and a separate

set -Eeuo pipefail

  got="$(sha256sum "${path}" | cut -d' ' -f1)"

    || { echo "REFUSE: $(basename "${path}") is ${got}, expected ${want}"; exit 1; }
  printf 'ok  %-16s %s\n' "$(basename "${path}")" "${got}"
