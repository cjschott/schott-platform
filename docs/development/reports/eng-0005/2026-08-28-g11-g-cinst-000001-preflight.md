> ## 🛑 RESULT: STOPPED — implementation defect, reviewer ruling required
>
> **The governed preflight of a first instance admission always refuses.**
>
> `admit_instance` ends with a guard comparing the freshly allocated identity
> against the record it supersedes. Under `rehearsing()` no identity is
> allocated, so `allocated` is `None`; for a first admission `supersedes` is
> also `None`; and `None == None` fires the guard. Every rehearsal of a
> non-superseding instance admission therefore refuses with
> **`supersedes-different-capability`** — a reason naming supersession for a
> request that supersedes nothing.
>
> **The write path is correct.** The identical body, written for real against a
> fixture, is `accepted` and produces a well-formed `CINST-000001`. Only the
> rehearsal refuses.
>
> **CINST-000001 was not created. No source was changed** — the brief forbids
> repairing governed behaviour inside a ceremony checkpoint, and this report
> does not. §9 states the defect, the mechanism, the blast radius and the
> options; §22 asks for the ruling.

### The gates, in the order they run

1. **Structure** — window ordering `admitted_until > admitted_at`,
   `admitted_at <= evaluated_at`; every identifier; scope well-formed.
2. **References resolve** — capability, contract, package, host, advertisement.
3. **No self-governance** — neither `actor` nor `approving_authority` may be
   `CHOST-0001` *or* `HOST-0001`: *"a machine does not admit itself into the
   fabric, under any identity."*
4. **Host is current and in service** — chain head, `availability_intent`.
5. **One binding, not four opinions** — package and contract both owned by the
   capability; package names the contract; the advertisement's host, contract
   and package all agree.
6. **Versions** — declared by the package *and* advertised, set membership only.
7. **Clocks** — `observed <= evaluated_at < valid_until` (else
   `advertisement-not-fresh`), `observed <= admitted_at`,
   `evaluated_at < admitted_until`.
8. **Supersession compatibility** — only when `supersedes` is given.
9. **Trust, twice, in two domains** — package in `capability-package`, host in
   `fabric-node`, each once, through C3 and nowhere else; each verified subject
   must be the fabric subject it authorises; both scopes must be live.
10. **Resources** — §10.
11. **The intersection** — §11 of the Trust section; then capability, target and
    classification membership.
12. **Commit** — evidence assembled, record constructed, identity minted.

## 9. 🛑 The defect — preflight of a first admission always refuses

### The mechanism

`admit_instance` ends:

```python
kind, allocated = _commit(store, "capability-instance", evidence, ...)
# C1 allocates from a sequence that never reuses a value, so a fresh
# identity cannot be the identity it supersedes.
if allocated == supersedes or (prior_root is not None and allocated == prior_root):
    _refuse(REFUSED, REASON_SUPERSEDES_CAPABILITY)
```

and `_commit` under rehearsal:

```python
_constructed(kind, PROBE_IDS[kind], evidence, build)
if _REHEARSING.get():
    # The record is constructible and every governed check above has run.
    # Stop here: allocation is the first act that cannot be taken back.
    return kind, None
```

For a **first** admission `supersedes` is `None`. Under `rehearsing()`
`allocated` is `None`. `None == None` is `True`, and the guard fires.

**The guard is correct for a write and meaningless for a rehearsal.** It exists
to prove a freshly minted identity is not the one it supersedes. Under a
rehearsal nothing is minted, so there is nothing to check — and it compares two
absences instead.

### Proof

```
1. rehearsal, supersedes=None (a first admission)
     outcome=refused  reason=supersedes-different-capability
     -> expected 'preflight', got a REFUSAL naming supersession

2. the IDENTICAL body written for real, same fixture shape
     outcome=accepted  record_id=CINST-000001
     -> the write path is correct; only the rehearsal refuses

3. rehearsal with supersedes='CINST-000001' (a migration)
     outcome=preflight  reason=None
     -> reaches preflight, because None == 'CINST-000001' is False
```

Case 3 is the control that isolates the cause: the same code path, the same
store, differing only in whether `supersedes` is `None`.

### Operator-visible symptom, against production

```json
{
  "operation": "admit-instance",
  "outcome": "preflight",
  "would_accept": false,
  "rehearsal_outcome": "refused",
  "rehearsal_reason": "supersedes-different-capability",
  "predicted_record_id": "CINST-000001",
  "destination_exists": false,
  "mutated": false,
  "request_digest": "sha256:ad1094ba4712d184995e9c16c3963836411fbc44ef400368f5c9ae006fca259f"
}
```

**exit 1.** An operator running the released pre-write gate on a correct body is
told the admission would be refused, and is given a reason about supersession
for a request that supersedes nothing.

### Blast radius

```
$ grep -n "allocated == supersedes" tools/fabric/admission.py
1719:        if allocated == supersedes or (prior_root is not None and allocated == prior_root):
```

**Exactly one occurrence, in exactly one operation.** No other governed
operation carries this shape. The scope of the defect is:

- `admit-instance --preflight` **with `supersedes` absent** — always refuses;
- `admit-instance --preflight` **with `supersedes` present** — works correctly;
- `admit-instance` **without `--preflight`** — correct in both cases.

So the *only* unreachable case is the rehearsal of a first admission — which is
precisely `CINST-000001`.

### How it was missed

Only two operations are exercised through `--preflight` anywhere in the suite:

```
1  select              (added by G11-C)
1  declare-package
```

`admit-instance` has never been preflighted in a test. G11-C added the rehearsal
boundary to selection and proved it there; the instance path inherited
`command_preflight` without a case that runs it.

### What this checkpoint did NOT do

**No source was changed.** The brief is explicit: *"Do not repair governed
behavior inside this ceremony checkpoint. Document the defect and request
reviewer ruling."* A one-line correction is visible from the proof above, and it
is deliberately not made here — a governed-behaviour change belongs in its own
reviewed checkpoint with its own RED evidence and its own test, not folded into
a ceremony.

## 10. Resource eligibility

Three distinct rules, and the advertisement is **not** one of them:

```python
# 9. Containment against what the operator verified, never what the host claimed
verified = host.get("verified_resource_profile")
if not isinstance(verified, Mapping) or dict(profile) != dict(verified):
    _refuse(REFUSED, REASON_RESOURCE_CLAIM)
requirements = package.get("resource_requirements")
if not isinstance(requirements, Mapping) or not satisfies(requirements, verified):
    _refuse(REFUSED, REASON_RESOURCE_CLAIM)
```

| Input | Value | Rule |
|---|---|---|
| body `verified_resource_profile` | `{architecture: x86-64}` | must **equal** the host's, exactly — not contain, not satisfy |
| `CHOST-0001.verified_resource_profile` | `{architecture: x86-64}` | the authority |
| `CPKG-0001.resource_requirements` | `{}` | must be `satisfies`-ed by the verified profile; the empty requirement is satisfied by anything |
| `CADV-000002.advertised_resource_profile` | `{architecture: x86-64}` | **not compared here** |

**The advertised profile is deliberately absent from this comparison.** It was
already contained against the host's verified profile at advertisement
registration; re-checking it at admission would let a self-report participate in
a decision the operator's attestation is supposed to own.

So the body's `verified_resource_profile` is `{"architecture": "x86-64"}` — one
dimension, because `EVID-000001` establishes exactly one. **No CPU, memory or
accelerator dimension is claimed**, and claiming one refuses (§13, control 17).

## 12. Advertisement consumption — and a derived finding

`CADV-000002` satisfies every consumption requirement:

| Requirement | Result |
|---|---|
| resolves | PASS |
| belongs to `CHOST-0001` | PASS |

| is the chain head | PASS *(not a rule — see below)* |

**`CADV-000001` refuses through the real rule** (§13, control 4):
`refused / advertisement-not-fresh`. Its expiry — not its supersession — is what
excludes it, which is the mirror image of G11-F's finding that expiry does not
bar *supersession*: expiry bars **consumption**, and here consumption is exactly
what is being attempted.

### Finding: admission gates on freshness, not head-ness

`advertisement_head()` is called from **one** place in the codebase:

```
tools/fabric/admission.py:1429   (register_advertisement, renewal rule R4)
```

`admit_instance` never calls it. Proven empirically (§13, control 5): a fixture
in which `CADV-000003` supersedes `CADV-000002`, leaving `CADV-000002` superseded
but still inside its window, **accepts** an admission against `CADV-000002`.

This is reported as derived semantics, **not as a defect claim**. In practice a
renewal is issued because the predecessor is near expiry, so the two conditions
usually coincide — but they are not the same rule, and a reviewer should know
which one is actually enforced. Whether admission *should* additionally require
head-ness is a design question this checkpoint does not decide.

### Finding: no committed authority sets an admission-window duration

`admitted_until` is required and unconstrained beyond ordering. The schema
declares `admission-expiry` as one of three expiry clocks alongside
`automatic_renewal: forbidden`, `automatic_readmission: forbidden`,
`recovery: requires-new-decision` — but **no accepted source states how long a
first admission should run.** No prior report sets one; no test asserts one.

The candidate therefore **proposes** 24 hours, mirroring the only accepted
bootstrap precedent (the 24-hour advertisement policy ruled on in S5-B2A), and
**flags it for explicit ruling** rather than presenting it as derived. Note the
interaction: with `admitted_until = 2026-08-29T11:49:13-05:00` the binding window
ends **2h 24m after `CADV-000002` expires**, so ELIG-6 would find the
advertisement stale before the admission window closes. That is coherent — the
clocks are independent — but the reviewer should choose it deliberately.

        │     allocate_id()                CINST-000001            --

                                     'CINST-000001' == None    None == None

                                            │                      │
                                       no refusal            _refuse(REFUSED,
                                            │                 'supersedes-different-
                                       ACCEPTED                     capability')
                                                                    │
                                                                 REFUSED

The guard proves a freshly minted identity is not the one it supersedes.

and therefore CINST-000001 exactly.
