## 6. ENG-0004 AC 25 — preservation evidence

**The criterion is retained, by identifier and by requirement.** The comment
block states it explicitly: *"THE CRITERION IS UNCHANGED. The Fabric completes
every §8 operation with no Health Runtime involved… THE PROOF IS REPLACED."*
AC 25 is not deleted, not renumbered, not narrowed, and no unrelated ENG-0004
test was touched.

**Why the old proof had to go.** `not (root / "tools" / "health").exists()` was a
sound proxy while Health was architecture-only. It stopped being a proof the
moment an authorised record model appeared: it would then fail for a reason that
says nothing about whether the Fabric depends on Health. **Absence of the
directory was never the criterion; independence was.**

**The replacement is strictly stronger** — it would also catch a Fabric that
imported Health while the directory was absent, which the old check could not.

### A. Static independence — *VERIFIED*

| Proof | Result |
|---|---|
| Fabric package located | 16 modules |
| No module imports `tools.health`, **by AST** not grep | `[]` |
| No module reaches health by relative import (`from .. import health`) | `[]` |
| No module pairs a dynamic-import mechanism with a health name | `[]` |
| No module requires health configuration or a health store | `[]` |

Parsing rather than grepping matters: a substring search is fooled by a comment
and blind to `importlib`.

### B. Behavioural independence — *VERIFIED, and this is the decisive part*

| Proof | Result |
|---|---|
| `tools.health` never entered `sys.modules` while all twelve §8 operations ran | passed |
| A meta-path blocker makes health genuinely unimportable | **self-verified** before use |
| `validate` raises nothing with health unimportable | passed |
| `validate` succeeds with health unimportable | passed |
| `validate` reports the **same counts** with health unimportable | passed |
| `inspect` succeeds with health unimportable | passed |
| `inspect` reports a populated store | passed |
| A **refused** invocation raises nothing with health unimportable | passed |
| An unusable invocation is still refused, not accepted | passed |
| **No operation attempted to import health** | `[]` |
| The scenario is torn down | passed |

`run()` drives the CLI **in this process**, so these are statements about the
real execution path rather than about source text. Both the success path and the
**refusal** path are exercised: a plane that needed health only on its error path
would still be a plane that needed health.

### C. Negative testing — *VERIFIED*

Against a **temporary fixture**, never by editing a Fabric module:

| Proof | Result |
|---|---|
| The AST barrier detects a forbidden static import (`from tools.health import records`) | detected `['tools.health']` |
| The dynamic-import barrier detects `importlib.import_module('tools.health.records')` | detected |

A barrier only ever run against a compliant tree has not been shown to reject
anything.

### D. Inertness and reachability — *VERIFIED*

| Proof | Result |
|---|---|
| `select_candidate`'s `health_removals` default is `()` | passed |
| No CLI option or subcommand can supply a health input — read off the **argparse parser**, recursively through subparsers, not off the source | passed |

Reading the parser means an option added later is seen; reading the source would
not necessarily show it.

### Stated limitation

**Dynamic-path coverage is strong but not total, and is not claimed to be.** The
behavioural blocker proves no health import occurred during the operations
exercised — twelve §8 commands plus `validate`, `inspect` and a refusal. It
cannot prove that *no conceivable* input would trigger one; a code path never
reached by those operations is not covered. The static AST pass closes the
import-time case, and the `importlib`/`__import__` pairing check closes the
obvious dynamic case. **No claim of complete dynamic-path coverage rests on grep
alone**, and none rests on grep at all.

## 9. U1 / U2 / U3 — reviewer decisions

*REVIEWER DECISIONS, recorded. No record model was changed in this increment.*

**U1 — `CHSTATE.review_required`: `CONTEXTUAL_VALIDATION_DEFERRED_TO_H10`.**
H1 enforces only what a record decides about itself. The `insufficient-policy`
leg is record-local and **is** enforced: the flag must be present and `true`. The
other two legs — arising from a null freshness policy, and from contradictory
evidence — are properties of the envelope and the observations, which H1 does not
hold, and belong to H10.

**The gap is explicit, and H1 does not claim complete contextual conformance:** a
CHSTATE that arose from a null freshness policy, carrying `state: unknown` and no
`review_required`, **will parse under H1** and is wrong under the schema. H1
cannot detect it. No H10 validation was implemented here.

**U2 — identical `from_state` and `to_state`: `DEFER_TRANSITION_SEMANTICS`.**
No new record-model prohibition was invented. The schema permits all seven values
in both fields and says nothing about equality, so H1 accepts it. Transition
semantics belong to the degradation-event derivation increment.

**U3 — `subject_id` format: `PRESERVE_SCHEMA`.** No undocumented identifier
pattern was introduced and the allowed subject types were not broadened. H1
requires a non-empty string, which is exactly what the committed schema requires.
