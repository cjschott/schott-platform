# v1.0 Engineering Ledger

The ledger is ordered by execution dependency, not identifier allocation.

Canonical sequence: ENG-0001 -> ENG-0002 -> ENG-0004 -> ENG-0006 -> ENG-0003

| ID | Work | State | Entry gate | Exit gate |
|---|---|---|---|---|
| ENG-0001 | Persist missing TLIN lineage records | Next | Operator Root ceremony complete | Test-first fix independently reviewed, released, and merged |
| ENG-0002 | Make `validate-store` genuinely read-only | Queued after ENG-0001 | ENG-0001 merged | Test-first fix independently reviewed, released, and merged |
| ENG-0004 | Fabric Runtime | Blocked by defect sprint | ENG-0001 and ENG-0002 merged and released | Runtime implemented and validated in reviewable increments |
| ENG-0006 | Health Runtime | Blocked by Fabric Runtime | Fabric Runtime exists and is validated | Health Runtime exists and is validated |
| ENG-0003 | TrustGateway cutover | Final production transition | Fabric Runtime and Health Runtime validated; required subjects seeded | Gateway uses `trust-plane-runtime` with no silent fallback |
| ENG-0005 | Capability Runtime | Future independently planned runtime work | Must be specified before implementation | Independently defined by its approved specification and plan |
| ENG-0007 | Capability Scheduler | Future | Runtime prerequisites and a separate approved specification | Independently defined by its approved specification and plan |
| ENG-0008 | Distributed Fabric | Future | Runtime prerequisites and a separate approved specification | Independently defined by its approved specification and plan |

TrustGateway cutover is intentionally not the gate for Fabric Runtime. The
Operator Root ceremony was the architectural gate. Cutover remains last so the
runtime can exist, be validated, and have its subjects seeded before production
traffic depends on it.

See [0002 - Runtime Sequencing Correction](0002-runtime-sequencing-correction.md).
